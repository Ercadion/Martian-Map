# Martian Map 개발 계획서

Nov 4, 2026 · @SongSangHyun

## 1. 개요

화성 표면의 한 지역에서 우주비행사가 어디로 걸어가 무엇을 조사할지 계획하는 **다층 지도와 경로 도구**를 만든다. 해커톤 전(11/14)까지는 지역·과학 목표를 정하고, 공개 아카이브 데이터로 엔진과 UI를 완성해 둔다. 챌린지 Resources가 공개되면 그 데이터를 읽는 어댑터만 추가한다.

**챌린지 요구사항 요약**

- 지역과 과학 목표를 정하고, 그곳의 Marswalk(화성 표면 탐사)를 계획·수행하도록 돕는다.
- 광학·열·분광·지형·대기·방사선 등 **3종 이상의 데이터를 겹친다**.
- 안전이 우선이다. 우주복 이동 제약과 큰 암석 같은 장애물을 피하는 경로, 우주기상 정보를 넣는다.
- 로버가 찍은 현장 사진으로 “도착하면 무엇이 보이는지”를 보여주면 좋다.
- 화면 형식은 자유다. 서식지 안 계획 화면, 태블릿, 헬멧 HUD 등이 가능하다.

**제품 목표:** 지역을 고르면 지형·광물·열·환경 레이어를 겹쳐 보여주고, 과학 정차 지점을 잇는 안전한 도보 경로와 각 지점의 현장 사진을 내놓는다. 이 정보를 우주비행사 헬멧 HUD와 로버 객실의 선체 투시 화면(아이언비전)으로 보여준다(6장).

**사전 단계 범위 (해커톤 전 완료)**

- [ ] 지역·과학 목표 확정(2장)
- [ ] 레이어 스키마와 어댑터 인터페이스 확정
- [ ] 공개 아카이브 데이터로 지역 데이터 팩 제작(지형·영상·광물·열·환경)
- [ ] 이동 비용 맵과 경로 엔진 구현, 테스트
- [ ] 지도·경로·POV UI를 mock과 실데이터로 끝까지 동작
- [ ] 데이터 공개 시 쓸 probe와 체크리스트 준비

**해커톤 범위:** NASA 제공 데이터 어댑터 → 레이어 교체·추가 → 경로 재계산 → UI 다듬기 → 제출물 제작

**산출물:** 웹 앱(데모 URL), GitHub 저장소, 30초 데모 영상, 발표 슬라이드

## 2. 미션 설정

**추천: 게일 크레이터 Mount Sharp의 박스워크(boxwork) 지대.** 화성 표면에서 방사선(RAD)과 기상(REMS)을 실제로 쟰 곳이라 ‘환경’ 레이어를 현장 실측값으로 채울 수 있고, 챌린지 본문이 직접 예로 든 목표다. 다른 팀과 겹칠 수 있어, 차별화는 경로 엔진과 HUD 화면에서 만든다.

| 후보 | 과학 목표 | 지형·영상 | 현장 환경 측정 | 현장 사진(POV) | 판단 |
| --- | --- | --- | --- | --- | --- |
| **게일 · Mount Sharp 박스워크** | 지하수가 남긴 광물 능선 조사, 굳은 능선에서 유기물 탐색 | HiRISE DTM·CTX 다수 | Curiosity RAD 방사선, REMS 기상 | Curiosity 하루 단위 원본 이미지 | 추천 |
| 제제로 크레이터 삼각주 | 고대 호수 퇴적층, 샘플 채취 지점 연계 | HiRISE DTM(착륙지) | MEDA 기상. 지표 방사선 측정기는 없음 | Perseverance 이미지 | 대안 |

**박스워크란:** 암석 틈에 지하수가 광물을 남기고, 주변 암석만 바람에 깎여 생긴 격자 모양의 낮은 능선이다. Curiosity는 2025년 5월 이 지대에 도착했다. 능선은 수 인치 높이지만 패턴은 수 마일에 걸쳐 있다. 황산마그네슘이 많은 층이며, 호수가 마른 뒤에도 지하수가 움직였다는 단서다([JPL](https://www.jpl.nasa.gov/news/nasas-curiosity-mars-rover-starts-unpacking-boxwork-formations/)).

**Marswalk 시나리오 (초안)**

1. 출발: 여압 로버 정차 지점
2. 정차 1: 능선과 골 사이 단면 관찰, 황산염 광맥 사진
3. 정차 2: 굳은 능선 암석 시료 채취(유기물 분석용)
4. 정차 3: 박스워크 경계부, 층 구성 변화 확인
5. 복귀: 같은 경로가 아닌 다른 안전 경로

정차 지점의 정확한 좌표와 총 이동 거리는 E가 11/6까지 Curiosity 경로·미션 블로그를 보고 정한다. 하루 EVA 제한(거리·시간)은 팀이 근거를 찾아 설정하고, 근거가 없으면 ‘사용자 설정값’으로 둔다.

## 4. 데이터 계층

모든 레이어는 어댑터를 거쳐 \*\*하나의 지역 격자(RegionPack)\*\*로 정렬된다. 엔진과 UI는 RegionPack만 읽는다. NASA 데이터가 오면 그 포맷을 읽는 어댑터만 추가하면 된다.

### 4.1 공통 규약

- **좌표계:** Mars 2000 구면(R = 3396.19 km), 동경 양수. 지역 내부는 지역 중심을 기준으로 한 등거리 원통 투영(미터 단위)을 쓴다. 어댑터가 원본 투영을 이것으로 바꾼다.
- **해상도 2단:** 상세층 1 m(HiRISE DTM 범위), 광역층 5 m(CTX 범위). 경로는 상세층 안에서만 계획한다.
- **시간:** UTC와 화성 솔(sol)을 함께 기록한다. 국지 태양시(LMST)는 계산 값으로 둔다.

### 4.2 내부 스키마

| 객체 | 필드 | 저장 |
| --- | --- | --- |
| RasterLayer | id, kind(elevation/image/mineral/thermal/ice/derived), units, res\_m, transform, nodata, source, acquired | COG |
| VectorLayer | id, kind(waypoint/hazard/unit/traverse), geometry, props, source | GeoJSON |
| EnvSeries | kind(dose\_rate/temp/pressure/uv/dust), t\_utc, sol, value, units, source | Parquet |
| SpaceWxEvent | type(FLR/CME/SEP), start, peak, note, link | JSON |
| PovImage | sol, camera, t\_utc, url, lon, lat, heading\_deg(있으면), source | JSON |
| RegionPack | id, name, center, bounds, crs, layers\[\], hazards\[\], waypoints\[\] | 디렉터리 + manifest.json |

### 4.3 어댑터

| 입력 포맷 | 어댑터 | 대상 데이터 |
| --- | --- | --- |
| PDS3 IMG+LBL, GeoTIFF, JPEG2000 | RasterAdapter (GDAL/rasterio) | HiRISE DTM·정사영상, CTX 모자이크, MOLA |
| WMTS 타일 | TrekWmtsAdapter | Mars Trek 배경 레이어 |
| PDS ASCII 테이블(+ .FMT) | PdsTableAdapter | RAD, REMS 시계열 |
| JSON API | DonkiAdapter | 우주기상 이벤트 |
| 웹 목록·JSON | RoverImageAdapter | Curiosity 원본 이미지 |
| Shapefile/GeoJSON | VectorAdapter | 지질 단위, SWIM 등 |

선택은 `datasources.yaml` 우선순위 목록으로 한다. 달 계획서와 같은 방식이다. `probe.py`는 위 포맷을 판별하고 CRS·해상도·단위·시간 범위를 리포트한다.

### 4.4 mock·합성 데이터

1. **합성 박스워크 지형:** 경사면 위에 격자형 능선과 바위를 생성한다. 정답 경로를 아는 케이스(평지는 직선, 벽이 있으면 우회)를 포함한다.
2. **합성 환경 시계열:** 일주기 기온·기압과 상수 + 잡음 선량률. UI 개발용이다.
3. **실제 축소 픽스처:** HiRISE DTM 하나에서 2 km × 2 km를 잘라 Git LFS에 올린다.

## 5. 분석 엔진

엔진은 ① 지형 파생 레이어 → ② 이동 비용 맵 → ③ 경로 계획 → ④ 정차 지점·환경 요약 순서로 돈다. 모든 임계값은 설정 파일에 두고, 근거가 확인되지 않은 값은 UI에 ‘설정값’으로 표시한다.

### 5.1 지형 파생 레이어

- **경사(°):** 1 m DTM에서 3×3 Horn 방식으로 구한다.
- **거칠기(m):** 5 m 창에서 평면 적합 후 잔차의 표준편차로 구한다.
- **단차(m):** 인접 픽셀 간 높이 차로 구한다. 박스워크 능선을 넘는 구간을 찾는 데 쓴다.
- **위험 등급:** 안전 / 주의 / 통행 불가 3단이다. 경사·거칠기·단차 임계값으로 나누고, 사람이 그린 장애물 폴리곤(VectorLayer hazard)을 더한다.

DTM 해상도(1–2 m)보다 작은 바위는 지형에서 잡히지 않는다. 그래서 바위 장애물은 HiRISE 정사영상(0.25 m)을 보고 수동으로 표시하는 것을 기본으로 한다. 자동 바위 검출은 확장 항목이다.

### 5.2 이동 비용

보행 속도는 지구의 토블러 보행 함수를 기준으로 하고, 우주복·화성 중력 보정은 계수 k로 둔다. k의 근거는 E가 조사하고, 없으면 사용자 설정값으로 둔다.

```latex
v(\theta) = k\cdot 6\,e^{-3.5\,|\tan\theta + 0.05|}\ \ \mathrm{km/h},\qquad \mathrm{cost}_{\text{cell}} = \frac{\Delta s}{v(\theta)}\,(1 + \beta\cdot\mathrm{roughness})
```

통행 불가 셀은 비용을 무한대로 둔다. θ는 이동 방향의 경사라서 오르막과 내리막 비용이 다르다.

### 5.3 경로 계획

- `skimage.graph.MCP_Geometric`(최소 비용 경로)을 기본으로 쓰고, 방향에 따라 달라지는 경사 비용이 필요하면 8방향 A\*를 직접 구현한다.
- 정차 지점 순서는 고정하고 구간별로 푼다. 복귀 구간은 왕로에 쓴 셀에 벌점을 주어 다른 경로를 유도한다.
- 출력은 폴리라인, 구간별 거리·예상 시간·최대 경사, 고도 단면, 경로 20 m 이내 주의 구간이다.
- 2 km × 2 km × 1 m(400만 셀) 기준으로 한 구간 3초 이내를 목표로 한다.

### 5.4 정차 지점과 환경 요약

- **정차 지점 카드:** 그 지점의 레이어 값(고도, 경사, 광물·열 지표)과 가장 가까운 로버 사진 3장을 보여준다.
- **방사선:** RAD 실측 선량률의 평균·범위에 EVA 시간을 곱한 값을 ‘참고 추정’으로 보여준다. 과거 측정치이므로 예보가 아니라고 표시한다.
- **기상:** REMS로 같은 계절(태양 경도 Ls)의 기온·기압 범위를 구해 EVA 시간대를 고르는 데 쓴다.
- **우주기상:** DONKI의 태양 플레어·코로나 질량 방출(CME)·고에너지 입자(SEP) 이벤트를 타임라인에 표시한다. 데모에서는 ‘SEP 발생 시 복귀’ 시나리오를 보여준다.
- **확장:** DTM 가시성 분석으로 로버·서식지와 직접 교신이 되는 구간을 표시한다.

## 6. HUD·UI 설계

화면은 두 모드다. **우주비행사 EVA 모드**는 헬멧 바이저 HUD로 걸으면서 볼 정보만 보여주고, **우주선 아이언비전 모드**는 우주선 안에서 선체를 투시한다. 화성에 다가가는 접근 비행 단계와, 착륙해 땅에 고정된 착륙 후 단계로 나뉜다. 팀 스케치를 바탕으로 만든 시안은 [Marswalk HUD 프로토타입](https://claude.ai/artifact/NZSXL6ucZHcVyA2ec4L2zK)에 있다.

### 6.1 설계 원칙

- **필수 항목은 NASA SUITS 기준을 따른다.** 본인·동료의 슈트·생체 원격측정, 2D 지도와 관심 지점, 에어록으로 돌아가는 브레드크럼, 이상치 경고(C&W), 과학 작업 알림이다. SUITS는 낮 조명을 고려하고 내비게이션이 시야를 방해하지 않아야 한다고 적는다([SUITS 2024 미션 설명](https://nasa.gov/wp-content/uploads/2023/09/fy24-suits-mission-description.pdf)).
- **시야 중앙은 비운다.** 정보는 바이저 가장자리에 두고, 경고와 다음 목적지만 시선 가까이 둔다.
- **색은 항공 HUD 관례를 따른다.** 녹색 심볼에 어두운 그림자를 넣어 밝은 화성 지형 위에서도 읽히게 한다. 주의는 주황, 경고는 빨강이고 항상 문구와 함께 쓴다.
- **통신 지연을 숨기지 않는다.** 지구와는 편도 약 3\~22.4분 지연이 있다([NASA Mars Relay Network](https://science.nasa.gov/mars/mars-relay-network/)). 즉시 대화는 동료·기지와 하고, 지구는 도착 예정 시각을 보여주는 비동기 메시지로 다룬다.

### 6.3 우주선 아이언비전 모드

- **개념:** Elbit Systems의 IronVision은 장갑차 승무원이 선체를 ‘투시’해 360° 주변을 실시간으로 보게 하는 헬멧 시스템이다([Elbit](https://elbitsystems.com/news/elbit-systems-introduces-ironvisiontm-helmet-mounted-system-armored-fighting-vehicles)). 우리는 이를 우주선 선체에 적용하고, 비행 단계에 따라 화면을 두 가지로 나눈다.
- **접근 비행(착륙 전):** 캐슐이 화성으로 다가간다. 화성 구체와 착륙 목표(게일 크레이터), 표면까지 거리, 접근 속도, 대기권 진입까지 남은 시간을 보여준다. 진입 절차는 순항 단 분리(진입 약 10분 전) → 대기권 진입(약 5.4 km/s) → 낙하산(진입 약 240초 뒤, 고도 약 11 km) → 착륙(진입 후 약 7분)이며 Mars 2020 보도자료를 따랐다([JPL](https://www.jpl.nasa.gov/news/press_kits/mars_2020/landing/mission)). 접근 속도는 화성 GM·반지름([NASA Mars Fact Sheet](https://nssdc.gsfc.nasa.gov/planetary/factsheet/marsfact.html))으로 쌍곡선 궁도 속도를 계산한다. 화성 자전을 반영해, 멀리서는 착륙 목표가 뒷면에 있다가 진입 시각에 정면으로 돌아온다. 시간은 ×60·×600·×3600으로 빨리 돌린다.
- **착륙 후(고정):** 착륙선은 땅에 고정되어 움직이지 않는다. 카메라 위치는 바뀜지 않고 시점만 돌려 360°를 본다. 밖에 나간 EV1·EV2의 위치·거리·O₂, 정차 지점, 통행 불가 지형을 추적한다.
- **공통:** 투시 ON/OFF로 창문만 있을 때와 비교한다. 패널은 단계에 맞춰 바뀐다. 접근 비행에서는 궁적 미니맵, 진입 절차, 캐슐 상태를, 착륙 후에는 지도, EV 경로, 객실·EV 상태를 보여준다.
- **실제 운용 가정:** 선체 외부 카메라·라이다 영상을 지형 모델 위에 합성한다고 가정한다. 프로토타입은 3D 렌더로 대신한다.

### 6.5 기술

프로토타입은 Three.js(WebGL)로 3D 지형을, SVG로 바이저·방위 테이프·객실 골격을, Canvas로 지도를 그린다. 본 개발에서는 React + TypeScript로 옮기고, 지형은 백엔드가 만든 타일·메시를 정적 파일로 배포한다. 조작은 드래그(둘러보기), WASD(걷기), M(전체 지도), Tab(모드 전환), H(귀환 경로)다.

### 6.5a 주변 지도·경로 계획·마커

아이언비전(착륙 후)에서 지도를 열면 착륙선이 가운데 고정된 **착륙선 주변 지도**가 나온다. EVA에서는 EV1이 가운데다. 두 모드 모두 같은 도구를 쓴다.

- 범위: 반경 100 / 200 / 400 m. 50·100·200 m 거리 링과 도보 귀환 한계 링(착륙선에서 300 m, 팀 설정값)을 그린다. 커서를 올리면 착륙선에서의 거리·방위, 그 지점 경사, EV1까지 거리를 보여 준다.
- 경로 지점 도구: 클릭한 순서대로 경유지 P1, P2 …를 놓는다. 끝에는 에어록 귀환이 자동으로 붙는다. EV1 현재 위치부터 A\* 초안 경로(하늘색 점선)를 바로 계산해 총 거리, 소요 시간(평균 0.99 m/s), 최대 경사, O₂ 소요량과 귀환 때 남는 O₂를 보여 준다. 25° 넘는 구간, 도보 귀환 한계 밖 경유지, O₂ 예비 15% 미만이면 주의를 띄운다.
- ‘EV팀에 경로 전송’을 누르면 현재 경로가 바뀌고 통신창에 \[HAB\] 메시지가 남는다. 되돌리기, 비우기, 기본 계획(남은 WP로 복원)도 있다.
- 마커 도구: 종류 4가지(과학 관심, 시료 채취, 위험, 메모)와 이름(24자)을 고르고 클릭해 놓는다. 큰 지도, 미니맵, 3D 화면(색 깃대 + 표지)에 모두 보이고, 놓을 때 착륙선 기준 거리·방위가 통신창에 기록된다. EVA에서는 160 m 안의 마커만 3D에 표시한다. 지우기 도구나 목록의 ×로 지운다.
- 해커톤 단계: 경유지·마커는 백엔드 `POST /plan`, `POST /markers`로 저장해 EV 화면과 기지 화면이 공유하게 바꾼다. 프로토타입은 브라우저 메모리에만 둔다.

### 6.5b EVA 슬트·외기 패널

바이저 아래 양쪽 모서리에 두 패널을 둔다(팀 스케치의 ‘아래쪽 우주비행사 상태’). 화면 높이가 모자라면 미니맵을 줄이고, 그래도 겹치면 NEXT STOP 패널을 감춘다(같은 정보가 ROUTE와 화면 중앙 안내줄에 있다).

- **SUIT · EV1 (왼쪽 아래):** 산소(%·남은 시간)·전력(%·소비 W) 막대, 슬트 압력 29.6 kPa, O₂ 탱크 MPa, 헬멧 CO₂ mmHg, 심박, 대사량 W, 냉각수 °C, 소모품 여유(O₂와 배터리 중 짧은 쪽), 누적 선량, EV2 상태·거리. 현재 값은 시나리오다.
- **ENV · 외기 (오른쪽 아래, 착륙 후 아이언비전에도 표시):** LMST, 기온, 지면 온도, 기압(지구 대비 %), 풍향·풍속, 돌풍, 상대 습도, 자외선 단계, 먼지 광학 깊이 τ, 선량률, 대기 성분 막대(CO₂ 95.1, N₂ 2.59, Ar 1.94, O₂ 0.16, CO 0.06 %), 일몰·일출까지 남은 시간.
- 대기 성분은 Curiosity SAM 측정값이다. 기온·기압·바람·습도·UV는 지금은 REMS 범위를 맞춘 하루 곡선이고, 해커톤 단계에서 REMS 실측 시계열(PDS)로 바꾼다. 화성 시간은 1 sol = 88,775초, 1시간 ≈ 3,699초로 계산한다.

### 6.5c 통신 두절 시 자율 귀환

화성에는 GPS가 없고 행성 자기장도 없어 나침반을 못 쓴다. 그래서 귀환 항법은 우주복 혼자 돌아가게 만든다. 여러 수단을 겹쳐 쓴다.

- **관성 항법 + 브레드크럼(기본):** 가속도계·자이로·걸음 수로 에어록에서의 이동을 누적하고, 5 m마다 지나온 점을 저장한다. 통신과 상관없이 항상 기록한다. 선례: Apollo 15\~17 월면차 항법 장치(자이로+바퀴 회전수로 착륙선 방위·거리 표시), NASA SUITS의 귀환 브레드크럼 요구사항.
- **지형 대조:** 헬멧 카메라 영상을 우주복에 미리 넣어 둔 궤도 지형 모델(HiRISE DTM)과 맞춰 누적 오차를 되돌린다. 로버 시각 주행계·지형 대조 항법과 같은 원리.
- **태양 나침반:** 현지 시각과 위치에서 태양 방위를 계산해 자이로 방위 드리프트를 잡는다. 밤에는 사용 불가(별·포보스로 대체 가능).
- **착륙선 비콘:** 통신망과 별개인 근거리 비콘으로 방향·거리를 잔다. 마스트 섬광등은 눈으로 보는 보조 수단.
- **운용 규칙:** 도보 귀환 한계(300 m) 안에서만 활동, 2인 1조(EV1↔EV2 직접 무선은 살아 있음), 응답 없음 90초면 작업을 멈추고 왜던 길로 귀환.

**프로토타입 구현 (‘통신 두절 시험’ 버튼)**

- HAB·MCC 채널은 ‘신호 없음’, 보낸 메시지는 대기열에 보관됐다가 복구 때 전송. EV2 채널은 계속 된다. 지도의 ‘EV팀에 경로 전송’은 실패 처리.
- EVA 화면: 착륙선을 가리키는 귀환 화살표(추정 위치 기준 방위·거리±오차), 미니맵·큰 지도에 브레드크럼과 위치 오차 원, RETURN 패널(착륙선 방위·거리, 위치 오차와 마지막 고정 수단, 관성·태양 나침반·비콘 상태, 브레드크럼 길이, 자동 귀환까지 남은 시간, 산소 기준 출발 마감).
- 오차 모델(시나리오): 출발 ±3 m, 걸은 거리의 2%(낮, 태양 나침반 사용) 또는 3.5%(밤) + 시간 드리프트로 증가. 비콘 반경 120 m 안이면 ±1.5 m + 거리의 1.5%로 줄고, 밖이면 45초마다 지형 대조로 ±6 m 보정.
- 90초 동안 응답이 없거나 H를 누르면 브레드크럼을 거꾸로 따라 귀환(검증된 길이라 A\* 새 경로보다 우선). 출발 마감 = 남은 O₂ 시간 − 예비 15% − 귀환 거리/보행 속도×1.15. 0 이하면 WARNING.
- 아이언비전(착륙 후): EV1 원격측정 ‘수신 없음’, 마지막 수신값, 비콘·섬광등 상태를 보여 주고, EV1은 선체 카메라로만 추적한다.
- 해커톤 단계: 브레드크럼과 지형 대조용 지도 타일을 클라이언트(우주복 측)에 미리 받아 두고, 서버 없이도 귀환 화면이 동작하도록 유지한다.

### 6.6 시선 추적 (노트북 카메라)

우주복 장갑을 끼면 손으로 작은 버튼을 누르기 어렵다. 그래서 눈으로 HUD를 다루는 입력을 하나 더 둔다. 노트북 웹캠으로 시선 위치를 추정하고, 화면에는 작은 원(레티클)으로 시선 위치를 보여 준다.

**기능**

- **패널 초점:** 바라보는 패널만 또렷하고 나머지 패널은 반투명(50%)으로 흐려진다. 패널 경계 바깥 20 px까지 같은 패널로 본다.
- **응시 클릭(dwell):** 버튼을 0.9초 바라보면 눌린다. 레티클 바깥 고리가 차오르며 진행을 보여 준다. 누른 뒤 1.2초는 다시 눌리지 않고, 같은 버튼은 시선이 떠났다가 돌아와야 다시 눌린다. 대상은 상단 바 버튼, 통신 채널 탭, 지도 닫기, EDL 확인 버튼이다.
- **표지 펼치기:** 3D 표지(정차 지점, EV1·EV2, 위험 지형, 바위, 착륙 목표)에 시선이 48 px 안으로 들어오면 세부 정보가 한 줄 더 펼쳐진다. 예: 정차 지점의 작업 내용과 체류 시간, EV1의 심박·배터리·누적 선량.
- **가장자리 시점 회전:** 화면 좌우 7% 띠를 바라보면 시점이 그쪽으로 돈다(최대 0.9 rad/s). 패널·상단 바 위이거나 위아래 끝(상단 20%, 하단 15%)이면 돌지 않는다. EVA, 착륙 후 아이언비전, 접근 비행 모두 같다.

**구현**

- 라이브러리: [WebGazer.js 3.3.0](https://webgazer.cs.brown.edu/) (Brown 대학, GPL-3.0). 얼굴·홍채 랜드마크를 브라우저 안에서 뽑아 시선 좌표로 회귀한다. 영상은 서버로 보내지 않는다.
- 시작 순서: `getUserMedia`로 카메라 권한부터 확인 → 통과하면 그때 WebGazer 스크립트를 CDN에서 불러옴 → `saveDataAcrossSessions(false)`, `applyKalmanFilter(true)`, 예측 점 숨김.
- 보정: 화면에 점 9개(가로·세로 10/50/90%)를 띄우고 각 점을 바라보며 3번씩 클릭한다. WebGazer는 클릭 위치를 정답으로 삼아 학습한다. 보정 중에만 카메라 미리보기를 오른쪽 아래에 띄운다.
- 떨림 줄이기: 칼만 필터 위에 지수 평활(α = 0.25)을 한 번 더 건다. 웹캠 시선 추정 오차는 보통 수 cm(화면에서 100\~200 px) 수준이라, 응시 대상은 버튼·패널 크기 이상으로 잡았다.
- 대체 입력: 카메라가 막히거나 없으면 이유를 안내하고 **마우스 체험 모드**를 권한다. 마우스 커서를 시선으로 보고 같은 기능이 모두 동작한다.

**고개 방향 연동**

- 추정: WebGazer가 이미 돌리는 얼굴 메시(468점)를 `getTracker().getPositions()`로 꺼낸다. yaw = atan2(−(z₂₆₃ − z₃₃), x₂₆₃ − x₃₃) (양쪽 눈꼬리), pitch = atan2(−(z₁₅₂ − z₁₀), y₁₅₂ − y₁₀) (턱·이마). 지수 평활 α = 0.35. 보정을 시작할 때의 자세를 정면(0°)으로 잡고, ‘지금 자세를 정면으로’ 버튼이나 C 키로 다시 맞춘다.
- 시선 보정(눈+고개 융합): 화면 시선 = WebGazer 추정 + a + k·Δ고개각. k의 기본값은 기하로 정한다(화면까지 55 cm, 화면 폭 30 cm 가정 → 라디안당 약 1.83×화면 폭 px). 9점 보정에서 각 점의 첫 클릭(모델이 그 자리를 아직 학습하지 않은 시점) 잔차를 모아, 기본값 쪽으로 끌어당기는 릿지 회귀로 a·k를 다시 맞춘다. 첫 3점은 모델이 너무 덜 학습된 상태라 빼고, 남은 샘플이 4개보다 적으면 기본값을 쓴다.
- 화면 회전: 고개 각도 변화를 3D 카메라에 1:1로 더한다(같은 방향·같은 각도). ±1.5° 데드존, yaw ±46°·pitch ±29° 제한, 약 0.12초 시상수로 부드럽게 따라간다. 등방위 테이프도 같이 돈다. 보행 방향에는 영향을 주지 않는다(둘러보기만). 고개 회전이 켜져 있으면 가장자리 시점 회전은 꺼서 두 번 돌지 않게 했다.
- 표시: 인식된 시선 위치는 형광 빨간 점(#ff1f4b, 발광)으로 항상 보여 주고 보정 중에도 보인다. 상단 바에 현재 고개 각도를 표시한다.
- 대칭 문제 대비: 카메라에 따라 좌우가 반대로 나오면 ‘좌우 반전’으로 뒤집는다. 화면 회전만 따로 끌 수도 있다.

**실행 환경 제약:** claude.ai 아티팩트 화면은 카메라 접근이 막혀 있어 마우스 체험만 된다. 카메라 모드는 내려받은 HTML을 Chrome에서 직접 열거나(file:// 또는 localhost), 팀이 HTTPS로 배포한 데모 사이트에서 동작한다. 첫 실행 때 모델 파일을 내려받으므로 인터넷 연결이 필요하다.

**라이선스 주의:** WebGazer는 GPL-3.0이다. 데모 앱 전체를 공개 저장소에 GPL 호환으로 올리면 문제가 없다. 다른 라이선스로 내야 하면 시선 추적을 별도 모듈로 분리하거나, MediaPipe Face Landmarker(Apache-2.0)로 홍채 위치를 직접 뽑아 간단한 회귀를 붙이는 대안을 쓴다.
